## 1. Назначение

Документ дополняет SRS и уточняет границы, роли и правила поведения, нужные для UML-моделирования динамических сценариев «Автоучёта» в лабораторной работе № 5.

## 2. Границы системы

**Входит в модель:** одно desktop-приложение на Java 17 / Swing; доменный слой; локальный JSON-журнал; окна главного экрана и формы расхода.

**Не входит:** сеть и внешние API, учётная запись и пароль, несколько автомобилей, график расходов, SQLite, компоненты ИИ/МО, мобильные клиенты.

## 3. Актёры

| Актёр | Роль |
|-------|------|
| Владелец автомобиля | Ведёт карточку машины, записывает и правит расходы, выбирает периоды, смотрит сводку и сравнение |

Внешних систем-актёров в версии 0.1 нет: приложение работает офлайн.

## 5. Правила поведения

| Тема | Правило |
|------|---------|
| Проверка ввода | Неверные поля не создают запись и не открывают журнал на запись |
| Пустой период | Итог 0.00 BYN, текст «Расходов за период нет», цена километра числом не показывается |
| Нехватка пробега | При менее чем двух показаниях или непроросшем пробеге показывается фраза, а не число |
| Сбой записи файла | Старый журнал остаётся; форма не очищается; в лог пишется причина без сумм и комментариев |
| Сравнение периодов | Если у второго периода начало позже конца, уже показанные числа не подменяются |
| Удаление | Выполняется только после подтверждения пользователем |

## 7. Описания потоков событий ключевых прецедентов

### UC-01. Добавить расход

* **Краткое описание.** Владелец вводит категорию, дату, сумму и необязательные поля; система проверяет ввод и сохраняет запись в журнал.
* **Предусловия.** Приложение запущено; карточка автомобиля доступна.
* **Основной поток.** Открыть форму → заполнить поля → «Сохранить» → проверка успешна → запись в память и в файл → обновить список и сводку → закрыть форму.
* **Альтернативы.** Ошибка поля — сообщение у поля, файл не меняется. Сбой записи файла — сообщение, лог, форма остаётся с введёнными данными.
* **Постусловия.** При успехе в журнале есть новый расход; сводка периода пересчитана.

### UC-02. Посмотреть стоимость владения за период

* **Краткое описание.** Владелец задаёт границы дат и видит итог, суммы категорий и цену километра либо фразу о нехватке данных.
* **Предусловия.** Приложение запущено.
* **Основной поток.** Выбрать период → система отбирает расходы → считает сводку → показывает числа (или пустое состояние).
* **Альтернативы.** `from` > `to` — период не применяется, прежние числа сохраняются.
* **Постусловия.** На экране актуальная сводка выбранного периода.

### UC-03. Сравнить два периода

* **Краткое описание.** Владелец задаёт второй период и видит две сводки и разность итогов.
* **Предусловия.** На главном экране доступен блок сравнения.
* **Основной поток.** Задать даты второго периода → посчитать обе сводки → показать разность.
* **Альтернативы.** Некорректный второй период — сообщение, числа не меняются. Пустой период даёт 0.00 BYN.
* **Постусловия.** Показаны две сводки и разность (второй минус первый).
